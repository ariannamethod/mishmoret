# Mishmoret · משמרת

מערכת ההרשמה של אנטר, באר שבע: בוחרים מתי ואיפה לומדים, רואים מי מגיע וקוראים את הודעות המרכז. פותחים קישור בדפדפן בטלפון או במחשב ונכנסים לחשבון האישי.

## מה עושים כאן?

- **נרשמים לשבוע:** בוחרים יום מראשון עד חמישי, בוקר / אחר הצהריים / יום מלא, ומהבית / בחממה. למשל: יום שלישי בבוקר, מהבית.
- **רואים מי איתי:** הלוח מציג את המשתתפים בכל יום ואת מקום ההשתתפות שלהם. אפשר לעדכן או לבטל את ההרשמה האישית.
- **מזמינים מקום:** בהגעה למרכז אפשר לבחור שולחן או חדר פנוי. הזמנה ליום מלא תופסת גם את הבוקר וגם את אחר הצהריים.
- **מנהלים את המרכז:** בלוח **״ניהול״** מוסיפים משתמשים, מפרסמים הודעות וסוגרים יום שלם או משמרת. סגירה מסמנת הרשמות קיימות כמבוטלות; פתיחה מחדש מחזירה אותן.

## מי יכול לעשות מה?

יש שני סוגי חשבונות: **משתתף / משתתפת** (`member`) ו־**מנהל / מנהלת** (`admin`). כרגע ארבעת חשבונות הצוות הראשונים הם חשבונות ניהול, ולכן כולנו רואים את לשונית **״ניהול״**. כשמוסיפים משתתפים, בוחרים עבורם את התפקיד המתאים. הכינוי **״דיקטטרורית״** מוצג רק ליד רעות ברשימת המשתמשים — זו הבדיחה שלנו, בלי הרשאות נוספות.

| פעולה | משתתף / משתתפת | מנהל / מנהלת |
| --- | --- | --- |
| צפייה בלוח, בשמות הנרשמים ובהודעות | כן, לאחר כניסה לחשבון | כן |
| הרשמה למשמרת ועדכון זמן, מקום או שולחן | עבור עצמך | עבור עצמך |
| ביטול הרשמה — לפי המימוש הנוכחי | הרשמה אישית בלבד | כל הרשמה |
| הוספת משתמשים, שינוי תפקידים והשבתת חשבונות | לא | כן |
| איפוס סיסמה למשתמש | לא | כן; מתקבלת סיסמה זמנית חדשה |
| פרסום ומחיקת הודעות, סגירה ופתיחה של משמרות | לא | כן |
| הוספת חדרים ושולחנות והשבתתם | לא | כן; מקום עם הרשמות עתידיות אינו ניתן להשבתה |
| שינוי הסיסמה האישית ושיחה עם איציק | כן | כן |

לשונית הניהול מוסתרת ממשתתפים, והשרת בודק הרשאות גם בפנייה ישירה אליו. כדי שלא נאבד גישה לניהול, אי אפשר להשבית את חשבון הניהול הפעיל האחרון או להסיר ממנו את תפקיד הניהול. בלי כניסה לחשבון אין גישה ללוח ולשמות. כרגע אין הרשמה עצמית: חשבון חדש נוצר דרך הניהול, ובכניסה הראשונה חייבים להחליף את הסיסמה הזמנית.

**כללי ההרשמה כרגע:** נרשמים לימים ראשון–חמישי, מהיום והלאה. לכל אדם הרשמה אחת בכל תאריך; שמירה נוספת לאותו יום מעדכנת את ההרשמה הקיימת. בוחרים בוקר, אחר הצהריים או יום מלא. חדר או שולחן אפשר להזמין רק בהגעה לחממה, ובכפוף לזמינות; הזמנת חדר שלם מתנגשת עם הזמנת שולחן באותו חדר ובאותו זמן. משמרת סגורה אינה מקבלת הרשמות חדשות.

**מה איציק יכול?** להציע הרשמה, להציג את הלוח ולהציג את ההרשמות שלך. רק לחיצה על **״שמירת משמרת״** שומרת את ההצעה. איציק אינו מבטל הרשמות, משנה הרשאות או מפעיל פעולות ניהול. השפם שלו לא מעניק הרשאות נוספות.

**ביטולים — ממתינים להחלטה עם רעות:** הטבלה מתארת את האפשרויות הקיימות באתר. נוהל הביטול של הלימודים עדיין צריך אישור מרעות, ובפרט האם ביטול יתבצע רק דרכה. לאחר ההחלטה נתאים את הרשאות הביטול ואת ההסבר כאן.

הרשאות ניהול באתר והרשאות הפיתוח ניתנות בנפרד: חשבון ניהול אינו מעניק גישה ל־GitHub או לשרת. בשלב הנוכחי אולג מאשר וממזג שינויים בקוד.

## דברו עם איציק 🐺

**איציק** הוא העוזר של משמרת, המופעל באמצעות Wolfe של Arianna Method. הוא מקבל את פניכם: **״אהלן, אני איציק. מתי ואיפה לומדים?״**

[Wolfe](https://github.com/ariannamethod/wolfe) הוא מודל נוירוני לקריאה לכלים (tool-calling), עם אפס משקולות מאומנות מראש (zero-weights), שפותח ב־**Arianna Method**. הוא ממשיך את הקו הארכיטקטוני של [PostGPT](https://github.com/ariannamethod/postgpt). כאן הוא משולב כמנוע החלטה בתוך שרת ה־C ובונה שדה עצבי אסוציאטיבי מהגדרות הכלים ומקורפוס הדוגמאות בעברית.

הכפתור הקבוע **״דברו עם איציק״ 🐺** פותח את הצ׳אט: בצד המסך במחשב, ובחלונית שעולה מתחתית המסך בטלפון. אפשר לכתוב לאיציק למשל: **״תקבע לי ליום שלישי בבוקר מהבית״**. איציק פותח הצעת הרשמה עם תאריך, זמן ומקום; בודקים את הפרטים ולוחצים על **״שמירת משמרת״** כדי להירשם. אפשר גם לבקש להציג את הלוח או את ההרשמות האישיות.

אם חסר פרט, איציק שואל עליו: למשל ״איפה לומדים — מהבית או בחממה?״. אפשר לענות בהודעה הבאה ״בחממה״; בקשה חדשה ומלאה נבדקת בפני עצמה. מעבר לשבוע אחר או יציאה מהחשבון מנקים את הבקשה שלא הושלמה.

איציק מחזיק בשלושה כלים: הצעת הרשמה, הצגת הלוח והצגת המשמרות שלך. הוא מתנהג כאילו הוא מנהל את כל המרכז. אין לו אפילו פונקציה להכנת קפה. שלושה כלים, אפס קפה, ביטחון עצמי של ועדת היגוי.

כשאיציק מכין הצעה, הוא עדיין מחכה לאישור שלך. אפילו מנהל מחלקת ימי שלישי לא יכול לשמור הרשמה בלי לחיצה על ״שמירת משמרת״. הבירוקרטיה ניצחה גם את הבינה המלאכותית.

## הפעלה ראשונה

מורידים את הקוד ונכנסים לתיקייה:

```sh
git clone https://github.com/ariannamethod/mishmoret.git
cd mishmoret
```

**ב־Mac**, עם Homebrew וכלי הפיתוח Command Line Tools:

```sh
brew install pkg-config libmicrohttpd sqlite libsodium json-c python
export PKG_CONFIG_PATH="$(brew --prefix sqlite)/lib/pkgconfig${PKG_CONFIG_PATH:+:$PKG_CONFIG_PATH}"
```

**ב־Debian, Ubuntu או Raspberry Pi OS:**

```sh
sudo apt install build-essential pkg-config libmicrohttpd-dev libsqlite3-dev libsodium-dev libjson-c-dev python3
```

אחרי התקנת התלויות:

```sh
make
./scripts/manage.sh start
```

פותחים את `http://127.0.0.1:8080` במחשב שמריץ את התוכנה. עוצרים עם `Ctrl-C`.

ההפעלה הראשונה יוצרת ארבעה חשבונות ניהול לצוות. סיסמאות הפתיחה האקראיות נשמרות בקובץ המקומי `data/initial-accounts.json`, שזמין רק לבעליו. מוסרים לכל אחד את פרטי החשבון שלו; בכניסה הראשונה בוחרים סיסמה אישית. לאחר מסירת הסיסמאות מוחקים את הקובץ. משתמשים נוספים מוסיפים דרך ״ניהול״.

שלושה מקומות מסומנים **״לדוגמה״**. דרך לוח הניהול אפשר להוסיף את השולחנות והחדרים של המרכז ולהשבית את מקומות הדוגמה.

## עובדים יחד

| חלק | איפה משנים? |
| --- | --- |
| העיצוב של שירה | `web/index.html`, `web/style.css`, `web/app.js` |
| השרת וכללי ההרשמה | `src/` — קוד C, עם SQLite לשמירת הנתונים |
| הפקודות והדוגמאות של Wolfe | `wolfe/tools.json`, `wolfe/examples.he.jsonl` |
| מנוע Wolfe והרישיון שלו | `vendor/wolfe/` |
| בדיקות | `tests/` |

לשינוי עיצוב עורכים את קובצי `web/` ומרעננים את הדף. אחרי שינוי קוד C מריצים `make` ומפעילים מחדש; שינוי הגדרות Wolfe דורש הפעלה מחדש. לכל מפתח עותק מקומי ומסד נתונים משלו. לפני שליחת שינוי מריצים:

```sh
make check
```

לפני ה־PR הראשון אולג מזמין את חברי הצוות לפי שם המשתמש שלהם ב־GitHub דרך `Settings → Collaborators → Add people`.

שולחים שינויים דרך Pull Request ב־GitHub. לפי נוהל העבודה שלנו, בשלב הראשון אולג מאשר וממזג; בהמשך אפשר להרחיב את הרשאות המיזוג לצוות. המאגר ציבורי כרגע ויעבור בהמשך למצב פרטי. למאגר מעלים את קוד הפרויקט; מסד הנתונים, הסיסמאות והגיבויים נשמרים מחוץ ל־Git.
